# نظام أعضاء الجمعية العمومية (`/members/`)

قاعدة بيانات مركزية لأعضاء الجمعية العمومية: العضويات، الاشتراكات والسداد، التجديد، التنبيهات، التقارير (Excel/PDF)، الاستيراد، والتدقيق. أُدمج من المستودع `agents` كنظام خامس داخل المنصة الموحّدة.

## كيف يندمج مع المنصة
| الجانب | التنفيذ |
|---|---|
| الدخول | صفحة دخول المنصة الواحدة؛ بوابة `gate('members')` في `server/index.js` تتحقق من الكوكي JWT وتضع `req.user`. لا حسابات أو جلسات خاصة بالنظام |
| من يرى النظام | صف `members` في جدول `public.apps` (يُنشأ تلقائيًا بالترحيل). الافتراضي: `admin, hr, finance, executive` |
| الصلاحيات | صلاحيات دقيقة (25) في `members.roles/permissions`، وجدول `members.role_map` يربط **دور المنصة** بدور النظام: `admin→مدير النظام`، `hr→مسؤول العضويات`، `finance→المسؤول المالي`، `executive→مشاهد`. تُعدَّل من الإعدادات › الأدوار والصلاحيات، ويُحدَّث `apps.roles` تلقائيًا ويسري فورًا |
| قاعدة البيانات | نفس قاعدة `hadiyah`، لكن جداول النظام في المخطط `members` (لا تعارض مع `users` و`audit_log` و`people`)؛ المفاتيح الأجنبية للمستخدمين تشير إلى `public.users` |
| الترحيلات | `modules/members/src/db/migrations/*.sql`، تعمل عند الإقلاع بعد `initSchema()` (قفل استشاري + checksum، إضافية فقط) |
| الواجهة | `modules/members/public` تُخدم على `/members/` مع شريط المنصة العائم؛ API على `/members/api/*` |
| CSRF | رمز عديم الحالة مشتق من كوكي الجلسة (`x-csrf-token` من `/members/api/auth/me`) + فحص `Origin` |
| التدقيق | `members.audit_logs` إضافة فقط (مشغّلات تمنع UPDATE/DELETE/TRUNCATE)، منفصل عن `audit_log` الخاص بالمنصة |

> وحدة الأعضاء CommonJS (`modules/members/package.json` يحدد `"type": "commonjs"`) بينما بقية المنصة ESM؛ تُستورد من `server/index.js` مباشرة.

## التشغيل
لا خطوة إضافية: `npm start` يهيّئ مخطط المنصة ثم ترحيلات الأعضاء. يحتاج PostgreSQL امتدادي `btree_gist` و`pg_trgm` (مسموحان لمالك القاعدة). لتوليد PDF يلزم Chromium (`CHROME_PATH`؛ صورة Docker تثبّته). المرفقات في `MEMBERS_UPLOAD_DIR` (الافتراضي `./uploads/members`، وفي Docker حجم `members-uploads`).

## النسخ الاحتياطي والاستعادة
نسخة قاعدة `hadiyah` الكاملة تشمل المخطط `members`: `pg_dump --format=custom "$DATABASE_URL" -f hadiyah.dump`، ويُنسخ معها مجلد `MEMBERS_UPLOAD_DIR`. الاستعادة: `pg_restore --no-owner -d <قاعدة>` ثم استعادة المجلد. النسخ تحوي بيانات شخصية: شفّرها وقيّد الوصول (PDPL).

## الاختبارات
```bash
TEST_DATABASE_URL=postgres://user:pass@localhost:5432/xxx_test npm test            # 68 اختبار تكامل للأعضاء + اختبارات المنصة
TEST_DATABASE_URL=... npm run test:e2e:members                                     # واجهة Playwright (يتطلب playwright عالميًا)
```
قاعدة الاختبار **تُعاد بناؤها بالكامل** ويجب أن ينتهي اسمها بـ `_test`؛ دونها تُتخطى اختبارات الأعضاء. تغطي: معايير القبول الاثنا عشر (إضافة/تعديل عضو، السداد الجزئي والمتعدد، حالات العضوية والسداد المستقلة، التجديد، مطابقة المؤشرات لقاعدة البيانات، تصدير Excel/PDF، الصلاحيات من الخادم، التدقيق، الاستيراد)، والتكامل مع المنصة (بوابة الدخول، `apps`، ربط الأدوار).

## الوثائق التفصيلية
- [افتراضات قواعد العضوية والمالية](members/ASSUMPTIONS.md) — **راجعها مع النظام الأساسي واللائحة**؛ قيم الاشتراك الافتراضية صفر حتى تُضبط
- [التنبيهات والربط المستقبلي بالبريد/SMS](members/NOTIFICATIONS.md) — الإرسال الخارجي غير مفعّل
- الأمن: Argon2/الجلسات صارت مسؤولية المنصة؛ يضيف النظام RBAC من الخادم، حجب الحقول المالية عمن لا يملك `payments.view`، رفع آمن للملفات، تدقيق إضافة فقط، تقنيع الجوال والبريد في السجل، واستعلامات مُعلَّمة وCSP صارمة. مخاطر معروفة: لا MFA، لا فحص برمجيات خبيثة للمرفقات، `exceljs` يعتمد `uuid` قديمًا (غير قابل للاستغلال هنا)، ويلزم قرار قانوني لمدد الاحتفاظ وحقوق أصحاب البيانات وفق PDPL، واختبار اختراق مستقل قبل الإنتاج.
