# افتراضات قواعد العضوية والعمليات المالية

هذه افتراضات تشغيلية افتراضية. **ما كان منها قابلًا للضبط يُعدَّل من الإعدادات دون تغيير الكود**، وينبغي مطابقتها مع النظام الأساسي ولائحة الجمعية.

## حالة العضوية (تُحسب في قاعدة البيانات – المشهد `member_overview`)
1. **ملغاة / معلقة:** قرار إداري مخزَّن، يتغلب على كل شيء، ويتطلب سببًا.
2. **سارية / قريبة الانتهاء / منتهية:** من تاريخ نهاية أحدث دورة. «قريبة الانتهاء» عندما يتبقى `rules.expiry_warning_days` (افتراضي 30) يومًا أو أقل. فترة السماح `rules.grace_days` (افتراضي 0) تؤخر «منتهية».
3. **لم تُفعَّل بعد (pending):** لا دورة، أو الدورة لم تبدأ، أو لم يبلغ المسدد الحد `rules.activation_min_paid_percent` (افتراضي 0 = لا يُشترط سداد).
4. **إنهاء بسبب التأخر المالي** غير مفعّل افتراضيًا (`rules.expire_overdue_days` = 0). فصل الصلاحية عن السداد هو الأصل.
5. التجديد المبكر: العضو الذي له دورة قادمة لا يظهر «قريب الانتهاء» لأن التغطية تُقاس بأحدث نهاية.
6. مؤشر لوحة التحكم «عضويات سارية» = سارية + قريبة الانتهاء، ويُعرض «قريبة الانتهاء» مؤشرًا مستقلًا.

## حالة السداد (لكل اشتراك، مستقلة عن الصلاحية)
`معفى` ← `مسدد بالكامل` (المسدد ≥ المستحق) ← `متأخر` (الاستحقاق مضى وبقي متبقٍ، حتى لو جزئيًا) ← `مسدد جزئيًا` ← `غير مستحق بعد` (الاستحقاق قادم ولا سداد) ← `غير مسدد`.
- «التقرير الجزئي» يضم كل من 0 < المسدد < المستحق بصرف النظر عن التأخر.
- حالة العضو المالية = «متأخر» إن وُجد أي اشتراك متأخر، وإلا حالة أحدث اشتراك.
- إجماليات المستحق/المحصل/المتبقي تشمل كل الدورات (دون المعفاة والملغاة) للأعضاء غير المؤرشفين.

## الدورات والتجديد
- نهاية الدورة شاملة = البداية + المدة بالأشهر − يوم. لا يُسمح بتداخل دورتين فعالتين للعضو (قيد قاعدة بيانات).
- التجديد ينشئ دورة + اشتراكًا جديدين؛ البداية الافتراضية: اليوم التالي لانتهاء السابقة، أو اليوم إن كانت منتهية. الاستحقاق الافتراضي = بداية الدورة. تجديد ثانٍ لدورة قادمة يتطلب تأكيدًا. لا تجديد لعضوية ملغاة.
- قيم الاشتراك الافتراضية للأنواع الثلاثة المبدئية **صفر** (لم تُزوَّد قيمة رسمية) — اضبطها من الإعدادات > أنواع العضويات.
- الإعفاء مسموح فقط للأنواع المعلَّمة «تسمح بالإعفاء» (الفخرية افتراضيًا)، وبصلاحية تعديل الاشتراكات، ولا يُسجَّل سداد على اشتراك معفى.

## المدفوعات
- لا تُحذف أبدًا؛ الإلغاء بحالة `voided` + سبب. التعديل بسبب إلزامي ويُدقَّق قبل/بعد.
- السداد لا يتجاوز المتبقي (قفل صف الاشتراك داخل معاملة). مرجع الحوالة/الإيصال فريد عالميًا للعمليات المؤكدة. مفتاح idempotency يمنع الإرسال المزدوج. تطابق (مبلغ+تاريخ+طريقة) بلا مرجع يتطلب تأكيدًا.
- لا يُقبل تاريخ سداد مستقبلي. المبلغ المسدد عند الاستيراد يُسجَّل كدفعة «رصيد افتتاحي» ولا تُعدَّل.
- «السداد الناجح» = معاملة قاعدة بيانات مكتملة (COMMIT) بعد شاشة مراجعة وتأكيد في الواجهة.

## الأرشفة
الأرشفة إخفاء من القوائم والمؤشرات دون حذف أي بيانات مالية؛ تُستعاد لاحقًا. لا يوجد حذف نهائي للأعضاء (قيود المفاتيح الأجنبية تمنعه).
