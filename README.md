# منصة هدية الحاج الموحّدة

مشروع واحد يجمع الأنظمة على **رابط واحد** و**تسجيل دخول واحد** و**قاعدة بيانات PostgreSQL واحدة**، بسجل موظفين وهيكل تنظيمي وصلاحيات وسجل عمليات مركزية.

| المسار | النظام |
|---|---|
| `/` | يفتح بوابة الموظفين مباشرة (بلا دخول)، وفي أعلاها «الدخول على الأرصدة» و«الدخول على التقارير» |
| `/login/` | تسجيل الدخول الموحّد + بطاقات المنصات المتاحة للمستخدم |
| `/portal/` | بوابة الموظفين (دليل الموظفين، الهيكل، الروابط، السياسات، المواقع، الهوية البصرية) |
| `/portal/admin/` | لوحة تحكم محتوى البوابة |
| `/hr/` | **متابعة أرصدة الإجازات**: جدول يعبّئه المسؤول (الرقم الوظيفي، تاريخ التعيين، الراتب الإجمالي، الرصيد السنوي والكلي، المستهدف، المستخدم) وتُحسب منه التكلفة المالية والتوفير تلقائياً؛ والنظام التفصيلي السابق (حركات واستحقاق) محفوظ في القائمة الجانبية |
| `/card/` | مصدر بطاقة الموظف بتصميم `card_staff.pdf` (يجلب الاسم والمسمى والقطاع والتحويلة من سجل الموظف، والصورة تُرفع من الجهاز) |
| `/report-builder/` | منشئ التقارير (مرتبط بالصلاحيات المركزية؛ دور `report_admin`) |
| `/admin/` | **الإدارة المركزية**: الموظفون، الهيكل، المستخدمون، الأدوار والصلاحيات، المنصات، الجلسات، سجل العمليات، الإعدادات |

في كل نظام زر عائم «المنصة» للتنقل (مكوّن مشترك واحد: `public/appbar.js`، أيقونات Lucide).

## ماذا يعني «مترابطة فعلاً»

- **جدول موظفين واحد** `employees` تقرأه وتكتبه كل المنصات عبر `services/employees.js`. تعديل الاسم أو المسمى أو الصورة أو الوحدة ينعكس فوراً في البوابة والبطاقة والإجازات.
- **هيكل تنظيمي واحد** `org_units`؛ نقل موظف أو إعادة تسمية وحدة تظهر في كل مكان، ويُحفظ التاريخ (`org_history` و`db_change_log`).
- **حساب الدخول منفصل عن الموظف** (`users.employee_id` اختياري).
- **صلاحيات مركزية RBAC** لكل منصة وعملية (عرض، إضافة، تعديل، حذف، اعتماد، تصدير…) مع نطاق بيانات (نفسه، التابعون له، القسم، الإدارة، القطاع، كل الجهة)، تُفرض في الخادم على كل API. الرفض افتراضي.
- **جلسات** قابلة للإنهاء إدارياً، وقفل بعد محاولات فاشلة.
- **سجل عمليات** `audit_logs` للإضافة فقط يُعرض في لوحة الإدارة (من دخل، ماذا غيّر، متى، قبل/بعد، من أي عنوان)، **وتسجيل لتغييرات القاعدة المباشرة** (psql/pgAdmin).

التفاصيل والقرارات والمخطط (ERD): [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## التشغيل

المتطلبات: Node.js 20+ و PostgreSQL 14+.

```bash
npm install
cp .env.example .env         # عدّل القيم (قاعدة البيانات، JWT_SECRET، ADMIN_PASSWORD)
npm run setup                # ينشئ القاعدة والجداول والمدير، ويستورد بيانات البوابة
npm start                    # http://localhost:3000   (يطبّق الترحيلات المعلّقة تلقائياً بعد نسخة احتياطية)
npm test                     # اختبارات؛ تحتاج PG_ADMIN_URL لإنشاء قواعد مؤقتة
```

**الترقية من نسخة سابقة**: `git pull && npm install --omit=dev` ثم أعد التشغيل؛ تُؤخذ نسخة في `backups/` ثم تُطبَّق الترحيلات. للمراجعة قبل ذلك: `npm run db:report` (تقرير تكرارات وتعارضات)، و`npm run db:backup` (نسخة يدوية). النشر: [`docs/DEPLOY.md`](docs/DEPLOY.md).

الأوامر: `db:create` · `db:seed` · `db:import-legacy` · `db:migrate` · `db:backup` · `db:report` · `build:card` · `build:icons`.

## البنية

- `server/` — خادم Express: `index.js` (المسارات والبوابات)، `routes/` (الإجازات القديمة + `core.js` الإدارة المركزية + `platform.js`)، `services/` (employees · org · users)، `lib/` (rbac · audit · sessions · settings · portalData …)، `db/` (schema.sql الأساسي + `migrations/` + backup + report).
- `public/` — `login/` (الدخول)، `admin/` (الإدارة المركزية)، `hr/` (الإجازات)، `shared/icons.js` (Lucide)، `appbar.js` (قائمة التنقل).
- `modules/portal` · `modules/card` · `modules/report` — واجهات ثابتة. بيانات البوابة تُخدَّم من `/portal/data/*.json` مباشرة من PostgreSQL فلا تتغير صفحاتها.
- `docs/` — `ARCHITECTURE.md` · `DEPLOY.md` · `HR.md` · `DESIGN.md`.

## ملاحظات

- بوابة الموظفين مفتوحة بلا دخول افتراضياً؛ من الإدارة المركزية ← الإعدادات يمكن إلزام الدخول (`portal_public`). الأنظمة الأخرى تتطلب دخولاً دائماً.
- الأدوار: مدير النظام، الموارد البشرية، المالية، الإدارة العليا، مدير قطاع/إدارة/قسم، موظف، مدير محتوى البوابة، مدقق — ويمكن إنشاء أدوار جديدة وتعيينها لعدة مستخدمين.
- الملفات المرفوعة (صور الموظفين وPDF والصور) تُحفظ في `modules/portal/policies` و`modules/portal/images`؛ **انسخها ضمن النسخ الاحتياطي** مع القاعدة.
- لم يُحذف أي جدول قديم (`people`, `audit_log`)؛ تنتظر موافقتك بعد التحقق (انظر ARCHITECTURE.md).
- البطاقة (أمام وخلف) بتصميم `card_staff.pdf`؛ صورة الموظف يرفعها المستخدم من جهازه ولا تُسحب من سجله.
