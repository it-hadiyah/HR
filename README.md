# منصة هدية الخير الموحّدة

مشروع واحد يجمع أربعة مشاريع كانت منفصلة، على **رابط واحد** و**صفحة دخول واحدة** و**قاعدة بيانات PostgreSQL واحدة**:

| المسار | النظام | المصدر السابق |
|---|---|---|
| `/` | يفتح بوابة الموظفين مباشرة (بلا دخول)، وفي أعلاها «الدخول على الأرصدة» و«الدخول على التقارير» | جديد |
| `/login/` | صفحة تسجيل الدخول الموحّدة + بطاقات الأنظمة حسب صلاحية المستخدم | جديد |
| `/portal/` | بوابة الموظفين (دليل الموظفين، الهيكل، الروابط، السياسات، المواقع، الهوية البصرية) | المستودع `cluade-ai` |
| `/portal/admin/` | لوحة تحكم البوابة (تعمل الآن على PostgreSQL بدل ملفات JSON و`api.ashx`) | `cluade-ai/admin` |
| `/hr/` | أرصدة الإجازات وتكلفتها المالية | المستودع `hr` |
| `/card/` | مصدر بطاقة الموظف (مع اختيار الموظف من الدليل) | المستودع `card` |
| `/report/` | تقرير تقييم مراكز التوزيع الخيري | المستودع `report` |

بعد الدخول يظهر في كل نظام زر عائم «☰ المنصة» للتنقل بين الأنظمة والعودة للصفحة الرئيسية.

## كيف ترتبط البيانات (قاعدة `hadiyah`)

```
org_units (الهيكل التنظيمي الواحد) ◄── people.org_unit_id      دليل الأشخاص (الرقم الداخلي، الاسم، البريد، الصورة)
        ▲                                   ▲   ▲
        │                                   │   └── users.person_id          حساب الدخول ← الشخص
        └── employees.org_unit_id           └────── employees.person_id      موظف الإجازات ← الشخص (واحد لواحد)
employees ──► leave_transactions, targets, snapshots …  (نظام الإجازات)
apps (التطبيقات وأدوار كل منها) · users (حساب واحد لكل الأنظمة) · audit_log (سجل تدقيق واحد)
link_categories → links · policy_categories → policies · locations · portal_docs · portal_backups   (بوابة الموظفين)
```

- **هيكل تنظيمي واحد:** وحدات البوابة (`org_units.slug`) هي نفس وحدات الإجازات، فيرى النظامان القطاعات والإدارات نفسها.
- **هوية واحدة للموظف:** جدول `people` هو دليل البوابة والبطاقة؛ ويُربط به موظف نظام الإجازات بـ `employees.person_id`.
  الربط التلقائي (زر في الصفحة الموحّدة للمدير والموارد البشرية) يطابق الرقم الوظيفي مع الرقم الداخلي أو الاسم، وما لا يتطابق يُربط يدوياً (`PUT /api/people/:id/link`).
- **حساب واحد:** جدول `users` للجميع، والأدوار تحدد التطبيقات المتاحة من جدول `apps` (عدّله بـ SQL لتغيير من يرى ماذا).

الأدوار: `admin` مدير النظام، `hr` الموارد البشرية، `finance` المالية، `executive` الإدارة العليا، مديرو القطاع/الإدارة/القسم،
`content_admin` مدير محتوى البوابة، `employee` موظف عادي (البوابة وبطاقة الموظف). مستخدم جديد: من «الإدارة والإعدادات» في نظام الإجازات.

## التشغيل

المتطلبات: Node.js 20+ و PostgreSQL 14+.

```bash
npm install
cp .env.example .env         # عدّل القيم (قاعدة البيانات، JWT_SECRET، ADMIN_PASSWORD)
npm run setup                # ينشئ القاعدة والجداول والمدير، ويستورد بيانات البوابة القديمة ويربطها
npm start                    # http://localhost:3000
npm test
```

`npm run setup` = `db:create` (ينشئ القاعدة والمستخدم عبر `PG_ADMIN_URL`) ثم `db:seed` (الجداول + المنشأة + المدير) ثم `db:import-legacy` (بيانات `server/db/legacy/*.json`).
إن كانت القاعدة منشأة مسبقاً فشغّل `npm run db:seed && npm run db:import-legacy` فقط. التفاصيل الكاملة لنشر الخادم في [`docs/DEPLOY.md`](docs/DEPLOY.md).

## البنية

- `server/` — خادم Express واحد: `index.js` (المسارات والصلاحيات)، `routes/` (واجهات الإجازات + `platform.js` + `portalAdmin.js`)، `lib/portalData.js` (تحويل بيانات البوابة بين الجداول وصيغة JSON القديمة)، `db/schema.sql`.
- `public/login/` — صفحة الدخول الموحّدة (`index.html`, `launcher.js`) والشريط العائم `appbar.js`؛ `public/hr/` واجهة الإجازات.
- `modules/portal`, `modules/card`, `modules/report` — واجهات الأنظمة الثابتة. بيانات البوابة تُخدَّم من `/portal/data/*.json` مباشرة من PostgreSQL فلا تتغير صفحاتها.
- `modules/card/tools/build.py` يبني `index.html` للبطاقة من `src/index.template.html` (`npm run build:card`).
- `docs/HR.md` — وثائق نظام الإجازات الأصلية، و`docs/DESIGN.md` تصميمه.

## ملاحظات

- بوابة الموظفين مفتوحة بلا دخول افتراضياً (`PORTAL_PUBLIC=1`)، والأرصدة والتقارير وبطاقة الموظف ولوحة تحكم البوابة تتطلب دخولاً دائماً. لإلزام الدخول للبوابة نفسها (فيها بريد وأرقام الموظفين) اضبط `PORTAL_PUBLIC=0`.
- لوحة تحكم البوابة لم تعد تعتمد على Windows Authentication: تُمنح لحسابات الدور `admin` أو `content_admin`.
- الملفات المرفوعة (PDF وصور) تُحفظ في `modules/portal/policies` و`modules/portal/images`؛ **انسخها ضمن النسخ الاحتياطي** مع قاعدة البيانات (`pg_dump`).
- إصلاحان في تقرير المراكز أثناء الدمج: أسطر مكسورة داخل بيانات المراكز كانت تُسقط السكربت، وعنصر `centerPanel` غير موجود.
- المستودعات الأصلية (`hr`, `card`, `cluade-ai`, `report`) لم تُعدَّل؛ هذا المستودع هو النسخة الموحّدة.
